# Firmware PR #96 — four-image ESP32-S3 flash ZIP remediation

## Root cause and unchanged identity

Old published artifact ID **13109297386** omitted `core-firmware/build/ota_data_initial.bin` from `.github/workflows/verify-core-tertiary-ble.yml` upload paths. The old build stage validated existence of every `flasher_args.json.flash_files` image **only in the workspace**, then selectively uploaded three binaries and a manifest. An upload action treats listed path matches as its content boundary: `if-no-files-found:error` does not detect an omitted path. The old published artifact is **NOT FLASH-READY** and must not be used.

This correction changes the packaging/CI/tests/docs **only**, preserving original approved Effects #95 renderer, user-requested third-color protocol in Firmware #96, `OT_FW_VERSION`, BLE HMAC authorization, STOP, universal output/trigger priority, crash-safe NVS and **unchanged 16MB dual-OTA partition CSV**. The verified firmware runtime source is unchanged; a new exact-SHA ESP-IDF v5.5.5 build is still required before using the replacement.

## Actual four-image reviewed offsets

Offsets are read from the **actual ESP-IDF-generated** `flasher_args.json` and independently cross-checked against the **actual ESP-IDF-generated** `flash_args`, source `partitions_ota.csv` and `sdkconfig.defaults`. A wrong offset, missing image or extra unexpected flash entry is fatal.

The package also includes the unmodified generated `flash_args`, `flasher_args.json`, reviewed `partitions_ota.csv` and `sdkconfig.defaults`, `SHA256SUMS.txt` and `opentail-flash-provenance.json` with every input hash, exact source SHA, IDF pin, chip and bench-only release status. No `sdkconfig`, partition, NVS bytes or firmware version were rewritten. OTA data is **copied directly from the same exact-SHA ESP-IDF build output** and is never fabricated, padded, regenerated by this packaging script, copied from an older version, or substituted from the repository.

### Revised CI and executable checks

Run the software-only unit tests (no flash):
```sh
python3 -m unittest -v scripts/tests/test_core_flash_package.py
```

The exact-head workflow runs unchanged CORE host and independent trigger regressions, Android source metadata and build-package source checks, then ESP-IDF 5.5.5. It runs:
```sh
python3 scripts/package_core_flash.py build \
  --build-dir core-firmware/build --project-dir core-firmware \
  --output core-firmware/releases/opentail-core-tertiary-complete-EXACT_SHA.zip \
  --source-sha EXACT_SHA
```
This creates the inner true flash ZIP and a `.zip.sha256` sidecar. Packaging validates all actual bytes and their archive CRC. GitHub Actions then uploads those two files **only after the full software gate succeeds**, downloads that exact artifact in a new job, and independently runs:
```sh
python3 scripts/package_core_flash.py verify \
  --zip downloaded-bench/opentail-core-tertiary-complete-EXACT_SHA.zip \
  --sha256-file downloaded-bench/opentail-core-tertiary-complete-EXACT_SHA.zip.sha256 \
  --source-sha EXACT_SHA
```
The verifier rejects every missing or extra path, duplicate/unsafe path, missing or altered OTA binary, mismatched offsets, bad internal `SHA256SUMS.txt`, corrupted metadata, ZIP CRC failure or outer checksum mismatch. The CI log emits the exact ZIP SHA256 and **all four individual image checksums/offsets**, making the result auditable. This is regression-guarded on negative cases and the **actual downloaded archive**, not just a build directory.

### Flash-readiness and operator constraints

After the final successful CI, download the GitHub Actions artifact named `opentail-core-tertiary-complete-<exact SHA>`; GitHub's outer artifact download contains the inner, independently SHA-verified ZIP and `.zip.sha256`. Extract the inner ZIP to one directory so `flash_args` and its four referenced image paths remain together. Verify the original SHA256 sidecar before attempting any bench operation. The installer command represented by the **original** generated manifest is:
```sh
python -m esptool --chip esp32s3 --port COM9 --baud 460800 write_flash @flash_args
```
**This is not authorization to flash the user's present vehicle controller.** The 16MB dual-OTA layout may need USB partition migration, while NVS at `0x9000` must be preserved. Never run full-chip erase. Independently confirm the connected ESP32-S3, power wiring, COM port, flash offsets and rollback risk before any owner-authorized isolated bench flash; leave vehicle OEM lamps connected. The existing generic `scripts/flash-from-github.ps1` searches a different named legacy artifact/branch; it is **not** upgraded or claimed compatible with the new nested ZIP, and it must not be used blindly for this candidate.
